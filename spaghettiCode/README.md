# 期末作業:把這份傳說中的遺留程式碼救回來

你接手了一份沒人看得懂、而且慢到令人絕望的程式碼。原作者已經離職,只留下一句
`// DO NOT REFACTOR - it took ages to get working`。它**功能是對的**,問題是它醜、
它慢,而且它故意用一堆指標和亂碼名稱把自己藏起來。

你的任務:**在不改變外部行為的前提下**,把它變成一份你願意簽名、而且跑得動的程式。

## 這次只有兩個檔案是重點

| 檔案 | 角色 |
| --- | --- |
| `b.c` | **產生測資**用的那支。它把輸入資料轉成一段密文當題目。其餘的 `.h` 都是它硬要拖著走的共用標頭。 |
| `a.c` | **本次作業重點:解密。** 它會 `#include "b.c"`,然後想辦法從密文把原文還原回來。又醜又慢的就是它。 |

編譯與執行:

```bash
gcc -O2 -I. -o b b.c && ./b -t        # 先確認四個內建測試都 ALL OK
```

```bash
gcc -O2 -I. -o a a.c && ./a           # 這支會跑很久,這也是題目的一部分
```

## 評分與自我檢測

`judge/` 資料夾裡有各作業系統的評分程式,可以拿來自我檢測(用法見 `judge/README.md`)。
正式評分用的題庫與金鑰由授課教師保管,和練習用的不一樣。

### 自動評分(push 後自動評)

你只要 `git push` 就好,這個 repo 本身不跑任何評分。老師的評分機**每 10 分鐘**會掃一次
全班的 repo,發現你有新的 commit 就用你拿不到的正式題庫評分,完成後:

- 你這個 commit 上會出現一個 **Autograder（正式）** 的檢查,標題就是你的分數,說明裡有你的
  排行榜代號與「下次可評分」時間;
- **匿名排行榜**(<https://ncku-se-115.github.io/scoreboard/>)也會更新你的名次。你的代號無法從帳號反推,就看上面那個檢查的說明,
  或老師發 repo 時給你的名冊。
- **正式成績取你歷次評分的最高分**,所以放心嘗試,分數不會因為某次改壞而往下掉。

> **每人每小時最多評分一次。** 冷卻時間內 push 的 commit **會直接略過、之後也不會補評**,commit 上會標
> 「冷卻中,○○ 後可評分」(台灣時間);請在那個時間之後**再 push 一次**才會評分。
> 所以請改好一個段落再 push,不要連續狂推。

想在交件前自己先測(含那支很慢的破解),直接在**本機**用 `judge/` 裡的程式,
見 `judge/README.md` —— 本機自測不受上面那個每小時一次的限制。

## 一句話

這份程式碼最危險的地方不是它醜,而是它**能動**。能動的爛程式碼會一直活下去,
直到某天沒有人敢碰它。所以這次作業沒別的,**就是要你好好地看一份醜 code**,
讀懂它、馴服它、讓它變快,而且全程不准弄壞它。

祝大家好運。
